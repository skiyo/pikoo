# 验证与发布

[English](release.md) | **简体中文**

## 按环境理解证据

[verification.json](verification.json)记录负载、镜像身份、单位和限制。结果适用于实测环境与构建，不自动适用于每个发布二进制或供应商。下载产物应通过发布清单和 SHA256SUMS 确认身份。

| 层次 | 能证明什么 | 不能证明什么 |
|---|---|---|
| 原生核心测试 | 状态、工具、取消、有界合成播放 | 板上调度或声音质量 |
| 本地 TLS 夹具 | 协议、凭证隔离、错误与重连 | 生产服务延迟和可用性 |
| 加速 PCM | 八小时等量合成负载与有界队列 | 板上真实运行八小时 |
| 板上工程负载 | 实测堆、栈、队列及已执行行为 | 所有家庭唤醒准确率或所有板型 |
| 归档与公开检查 | 文件完整性、本地链接、部分敏感模式 | 完整法律审查或识别所有可能密钥 |

记录的软件覆盖包括 ASan/UBSan 下 18 项服务行为、67 项 Python 工具检查、5 项预览、8 项装配指南、19 项生成规划器和 100 次网络夹具循环。加速负载覆盖 28,800 秒 PCM 与后端任务，虚拟播放欠载为零。具体源码修订的结果以 CI 为准。

板上证据包括语音、清单、记忆、搜索、重启读回、取消、鉴权失败恢复、告别和静音。持续流窗口为 120 秒，另有故障场景；内部堆低水位 27,308 字节，采样中最小的最大连续块 23,552 字节，后端栈余量 6,256 字节。JSON 明确记录测试镜像哈希和独立源码构建身份，不能把这些指标直接标到尚未刷入的二进制上。

自然儿童/家庭唤醒表现、主观听感、最终外壳 AEC、真实断电恢复和长稳需独立验收。生产服务覆盖与仅夹具覆盖的适配器也分别记录。

## 准备发布

1. 核对 `VERSION`、固件构建与 `release-plan.json` 的版本一致。
2. 校验公开示例并运行软件与网络检查。
3. 使用 ESP-IDF 5.5.5 和审核的模型/策略对构建目标板。
4. 检查分区余量、镜像身份、依赖声明和模型发布元数据。
5. 对板级变更执行明确负载的实机验证，保留私有数据并记录限制。
6. 打包并验证归档条目和校验和，排除 NVS、密钥、录音和家庭快照。

```sh
python tools/package-release.py --build firmware/build-dualeye \
  --model models/hi-pikoo/hi_pikoo.tflite \
  --checkpoint models/hi-pikoo/checkpoint.weights.h5 \
  --idf "$IDF_PATH" --output /absolute/output/pikoo-release
```

使用新输出目录。命令生成固件/模型 ZIP、清单和校验和，不发布、不访问 USB。模型发布检查验证与哈希绑定的权限记录，并保留非商业条款。

## 自动发布

`Publish release` 工作流通过 main 上手动触发或发布计划/工作流变更启动，等待同一提交的软件与公开检查通过，交叉编译、打包并添加仅应用 BIN。发布器确认 main 仍指向该提交，先上传到草稿，核对返回的大小与 SHA256，再公开 Release。

已公开的 Release 保持原样。`release-plan.json` 可选启用分支清理，只删除未保护、分支尖端已包含在检查提交内的 `codex/` 分支，删除前再次核对引用。保留 main、归档分支和未合入工作。普通文档编辑不会触发新的二进制发布。

## 发布资产契约

| 资产 | 内容 |
|---|---|
| 固件 ZIP | 源码、USB 安装器、匹配镜像、依赖声明 |
| 模型 ZIP | TFLite、checkpoint、策略、元数据、来源与条款 |
| 应用 BIN | 仅应用分区，常规升级使用安装器 |
| `release-manifest.json` | 源码/版本、目标、模型/策略和固件哈希 |
| `SHA256SUMS` | 下载完整性校验 |

使用者从[快速开始](getting-started.zh-CN.md)开始；维护者应保持验证范围准确，不把有限测试改写为通用可靠性承诺。
