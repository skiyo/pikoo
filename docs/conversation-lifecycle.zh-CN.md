# 会话生命周期

[English](conversation-lifecycle.md) | [简体中文](conversation-lifecycle.zh-CN.md)

更新：2026-10-17。本轮只改交互，不重新训练 V8D。

- 本地唤醒或主动按键唤醒后建立 WSS；连接中闭眼，收到 `voice.ready` 后睁眼。
- 将“你好皮酷”作为第一条用户消息提交，服务器直接回答，不需要再说一句。重复就绪通知、停止回答后的服务恢复、网络自动重连均不重复问候。
- 仅在**用户的最终识别文本**明确为“再见”“皮酷再见”“拜拜”“晚安”等告别短句时停止上行。等对应回答在硬件中播放完后断开 WSS、清除本次会话标识、闭眼待机。回答停滞时最多等待 20 秒；告别期间断网则直接回待机，不自动重连。
- 当前采用保守的整句匹配，尚不是任意表达的意图识别。“再见是什么意思”“不要说再见”等不会结束会话；未识别的告别说法仍可双击 BOOT 或等待无活动超时。
- 连接中、离线、静音、占用和凭证错误均闭眼，用文字区分原因；倾听、思考、说话时睁眼，保留正常眨眼。开闭眼约 220ms 过渡。使用明确的状态映射，修复思考与说话状态次序不同导致的显示错误。
- 意外断网重连保留近期会话标识；明确告别、主动结束及 30 秒无活动会清除。长期家庭记忆仍由服务器独立保存。

原生 C++ 与浏览器回归覆盖问候不重复、最终用户告别、否定句、硬件播放耗尽、回答超时、告别时断网和闭眼状态。自动检查不能替代真人唤醒、实机 AEC 和肉眼屏幕验收；实机记录另见设备验收文档。
