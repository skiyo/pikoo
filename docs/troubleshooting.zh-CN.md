# 故障排查

[English](troubleshooting.md) | **简体中文**

按最先失败的层次排查：USB → 配置 → Wi-Fi/TLS → 实时语音 → 推理与工具 → 播放。每次只修改一个因素，不要先擦除整片 Flash。

## 采集可安全分享的状态

```sh
python -m serial.tools.list_ports
python tools/device.py diagnose --port PORT --command status
```

记录固件版本、运行状态、静音/上传状态和错误码。公开报告不包含密钥、完整配置或家庭内容。新开串口前先关闭其他串口监视器。

| 现象 | 检查内容 | 下一步 |
|---|---|---|
| 没有 USB 端口 | 数据线、直连、供电、系统权限 | 重新列端口，更换已知可传数据的线，检查供电 |
| 有端口但占用或超时 | 是否被监视器或其他程序打开 | 关闭竞争程序，只保留一个维护进程，复位后重查端口 |
| `MIC OFF` | USB 导出或配置后是否保持静音 | 发送 `unmute`，不用重编译 |
| `USB SETUP` | 配置缺失或无效 | 本地校验 JSON，执行 `configure`，查询状态 |
| Wi-Fi 连接失败 | 2.4 GHz、名称、密码、信号、访问限制 | 修正配置，在普通可访问网络下验证 |
| TLS 错误 | 地址主机名、证书链、设备时间、网络 | 修复证书与连接，不能关闭证书校验 |
| HTTP 401/403 | 哪个服务失败、密钥与模型权限 | 只修正对应服务配置，再重试 |
| HTTP 429 | 限流或额度 | 检查服务商用量，等待退避，不连续手动重试 |
| 能聊天但工具失败 | 独立 LLM 地址、密钥、模型、函数调用 | 查看后端错误，先试只读清单请求 |
| 没有搜索工具 | `search.enabled` 与协议 | 单独配置搜索，再写入设备 |
| 不能读网页 | Tavily 提取能力、同源地址、HTTPS 目标 | 检查 `extract_url`，其他适配器不提供任意网页读取 |
| 说话断续 | Wi-Fi 抖动、帧错误、播放队列、堆内存 | 降低并发负载，记录计数器，以低音量测试 |
| 扬声器无声 | 静音、音量、接线、供电 | 核对硬件并取消静音，合适时再做声音测试 |
| 双眼方向不对 | 已保存的安装方向 | 使用 `rotate 90` 或 `rotate 270` |
| 安装提示备份不一致 | 备份是否对应设备当前内容 | 停止写入；确需更新时保留原备份并重新完整备份 |
| 升级提示分区不匹配 | 镜像与设备布局是否一致 | 按已备份的首次安装流程处理 |

## USB 传输被拒绝

传输要求设备处于静音待机且没有上传，工具发送数据前会自动请求该状态。被拒绝或超时时，先查询状态、排除串口占用，再检查固件兼容性。导入文件必须是有效快照，规范化后不超过 24 KiB。导出目标必须是新文件。导入和忘记配置后需要重启。

## 唤醒与音频诊断

在安静环境、自然距离下说完整的“Hi, Pikoo”。短按唤醒可以帮助区分唤醒检测问题与网络对话问题。反复大声喊、盲目改阈值或仅播放合成语音，都不能证明自然唤醒可靠性。检查麦克风开孔、扬声器接线和装壳声学效果。声音测试应单独安排，普通桌面检查保持静默。

声音断续时，记录是否出现欠载、发送帧错误、重连和堆内存不足。桌面测试延迟不等于真实 Wi-Fi 下的服务延迟；眼睛在动或 HTTP 请求成功不能单独证明音频链路已经修复。

## 恢复与反馈

复位后若 USB 名称改变，应重新选择端口。完整 Flash 恢复会覆盖配置和数据，仅用于恢复，不是日常升级方式，见[固件指南](firmware.zh-CN.md)。持续异常时提交准确步骤、板型、构建身份和脱敏诊断。预期行为见 [FAQ](faq.zh-CN.md)，私密漏洞报告见[安全说明](../SECURITY.zh-CN.md)。
