# Hi Pikoo 唤醒研究

[English](wake-hi-piku.md) | 简体中文

更新于2026-10-31。用户已在首次真实语料训练前确认：正式目标扩展为 **Hi＋piku 或 Hi＋piko**，记录为 `hi-piku-piko-v2`。仍须完整说出 Hi 和名字；Tikoo、单独名字及旧中文问候不属于目标。日常中文对话、服务器、音量和已安装模型保持原样。

## 实际证据与限制

- 两种独立因果网络分别为17,393／18,641参数；首轮训练后的 INT8 文件为40,080／42,576字节。权重小不代表实机速度或识别达标。
- 首轮2种时间配置×随机种子42／43已训练完，**四个候选均未通过完整已准入 DEV**。5次平滑／0.90时，最弱分组召回66.7%，6–7条负样本触发；最初按文件末尾计时还记录4–10次提前触发。主要混淆词为不支持的“Hi Tikoo”。这些失败保留，不称为封存测试。
- GPT 请求的童声被用户听成成人，因此按成人统计。本地 Qwen3 纯文本声线设计的 E／F 被听成女孩，G 被听成男孩；C／D／H未作为低龄来源准入。**它们都是合成音**，并不证明真人年龄、每条音频年龄或声线身份独立。
- 针对性扩充前共493条保留原音，267条准入、226条隔离。按预分配声线／提示家族分离 TRAIN 和 DEV。来源试听＋无提示本地 ASR 是有噪声的筛选，并非音素或年龄金标准。另有5条 piko 原音获用户逐条确认听成 ko；原清单和旧标签保留，新标签派生保存。
- 长音标提示生成过复读及多余内容，已停用配方并保留证据。来源试听原音不参与数值训练。真实儿童普通话原始 TRAIN 仅提供分层普通讲话负样本，不能证明目标词召回。
- 扩充前 OpenAI 累计估算约 **$0.217**，包含此前试听及一笔保守计入的不确定费用。**整轮上限$2，不是$20**。追加为固定100次成人 TRAIN 请求，共用原账本、逐次检查预算；不是自动无限扩充。用量估计及未知费用预留与平台最终账单分开。
- 修正准入和计时后的后续有限对照仍未合格，继续做一次仅 TRAIN 的本地扩充。尚无冻结、发布或烧录候选。本轮未使用家庭录音；此目标的家庭召回、ESP32耗时和8小时误唤醒尚未验收。

## 流程与边界

1. `hi_pikoo_contract.py` 明确目标版本，原记录不改写。
2. `hi_pikoo_generate.cjs` 使用既有授权 Key；独占锁、请求前预留、异常保守计费、不自动重试。区分试点、审核后 TRAIN 扩充、成人 DEV 和候选冻结后的 TEST。TEST 单独清单，须验证合格 DEV 和冻结模型摘要。不绕过童声策略，不切换付费来源。
3. `hi_pikoo_local_audition.py` 与 `generate_local_tts.py --jobs-file` 只复用已有本地模型，无参考录音、不下载模型。新生成原音继承预先确定的来源家族划分。
4. `hi_pikoo_review.py` 不提供目标转写或热词，离线盲转写；`hi_pikoo_admit.py` 结合原始转写、来源证据、保护摘要做准入。存疑、复读和缺词隔离，不裁切失败语音冒充完整正样本。
5. `hi_pikoo_train.py` 从头训练，2配置×2种子，每次最多30轮，DEV早停。当前检查点优先选择合格浮点 DEV，否则使用最弱组召回减每次误触发0.1、每次提前触发0.05的代理指标；最终仍须通过 INT8／Micro，不用浮点代理代替。合成 TRAIN 每条正／负分别12／6个变体；DEV原音及按摘要固定的前后位置不随 TRAIN 扩充变化。仅 TRAIN 做语速、房间、噪声增强及量化校准。公共语音按说话人限量，近似词／缺词负样本明确保留。
6. `hi_pikoo_verify.py` 校验训练后的逐步浮点序列／流式导出、INT8参考／原生Micro复位字节一致性，合格后才冻结。不读取封存 TEST 或家庭数据，不写设备。

命令入口见[英文说明](wake-hi-piku.md)。训练必须显式提供目标合同、准入清单、背景清单、保护摘要、固定上游和新私密输出目录；原始生成清单会被拒绝。导出故障可用 `--resume-export` 复用已保存权重，但必须验证输入摘要以及全部特征／标签／掩码逐元素一致，保留故障和恢复记录。

后续对照修正事件计时：20ms RMS、低于峰值40dB／最低5个PCM单位、额外40ms保护，排除文件末尾静音对时间戳的影响，**保留完整波形**。规则不查看模型得分，不证明音素完整；原文件末尾计时实验保留。家庭样本未参与该修改。

## 部署接口与验收

沿用16kHz单声道PCM16、30ms分析窗、10ms步长、40维前端、每30ms输入3帧INT8、输出标量概率。本机和固件使用相同float32循环平均。DEV比较3／5次平滑、0.80／0.85／0.90／0.95阈值；任何负样本或提前触发先判失败，再比较召回。每个正样本组召回须≥90%，p95延迟≤800ms；必须同时报告小分组数量和合成来源限制。

`wake-policy.json` 绑定模型摘要、双读音目标、前端指纹、冻结日期、DEV结果及触发参数。新 Hi Pikoo 候选须提供匹配配置；旧模型保持5次／0.90。源代码已用私密旧模型构建，不代表安装新模型。

未训练原型已通过浮点／静态及原生 TFLM 各300次调用／3次复位，主机arena为14,240／17,056字节；四个首轮训练模型也各通过8组平衡 TRAIN 特征、3次复位的原生Micro／参考内核字节一致性，arena同上；识别仍失败。**主机分配不等于板端内存和速度**。板端门槛仍为arena≤256KiB、前处理＋推理p99≤20ms／最大≤30ms，以及音频屏幕并发无看门狗或溢出。

冻结后依次完成全新独立 TEST、安全可恢复的实机资源测试、四人1米处两场各20次（每人每场≥18次）、8小时背景声（≤1次误唤醒）。家庭录音仅评估，不训练、清洗、增强、校准或选模；已消耗测试不能称为全新测试。
