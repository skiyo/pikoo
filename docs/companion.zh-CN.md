# 安静陪伴模式

[English](companion.md) | **简体中文**

明确唤醒后，Pikoo 保持连接，由 Gemini Live 判断是否需要回应。家人彼此聊天和背景音应保持安静；叫 Pikoo、询问它的看法或明确继续与它交流时回答。这依靠模型判断，不能保证每次都分清交流对象，也不识别说话人身份。

## 两端都需要开启

1. 服务器私密配置设为 `PIKOO_COMPANION_MODE=on`，确认没有通话后重启服务。公开模板默认 `off`。
2. 通过正常的仅应用升级流程，更新设备到 `0.2.0-bm17-comp1` 或之后版本，保留 Wi-Fi、凭证、屏幕方向和近期会话编号。
3. 通过已有 USB 诊断连接发送 `companion on`，或运行 `python tools/device.py diagnose --port YOUR_PORT --command 'companion on'`。设备将设置保存在 NVS，诊断显示 `companion=1`。
4. 明确唤醒后问候一次，保持连接、睁眼，取消 30 秒无活动自动待机。**此时麦克风音频会持续上传到服务器及 Google，直到静音、告别或明确结束。** 唤醒前待机、静音时仍不上行音频。

网页模拟器目前仍保留普通模式的 30 秒自动待机；这里的持久陪伴设置针对实机。长按 BOOT 静音，双击结束，播放时单击停止回答。支持完整短句“Pikoo，再见”“Goodbye, Pikoo”及原有告别说法；家人互相说的单独一句“再见”仍可能被保守短句匹配器命中。告别检测尚不是能判断交流对象的通用意图识别。

关闭时，设备发送 `companion off`，服务器设回 `off`，下次会话恢复普通行为和自动待机。本地唤醒模型没有改变。

## 原生接口与接入方式

Provider 发送 `proactivity: {proactiveAudio: true}` 及安静陪伴规则。2026-10-20 实测中，[官方能力指南](https://ai.google.dev/gemini-api/docs/live-api/capabilities#proactive-audio)列出的开关在当前 **v1beta** 地址返回 1007，提示字段不支持；同一模型和 Key 通过 **v1alpha** 接受并正常工作。因此只在开启陪伴时使用已验证的 Google v1alpha 地址，普通模式保留原地址。未验证的自定义地址明确报错，不能静默忽略设置；升级后需要复核。

`companion-runtime.mjs` 对固定版本 `qwen-audio-agent@2.0.1` 做组合适配：仅对 Google 麦克风自动回合停用“没有回复即故障”的计时器，并保持倾听状态。文字记录和回合清理照常工作；显式文字、工具请求与网络超时仍有原保护。不修改上游安装包，也不增加后台 LLM。

## 名字、上下文与记忆

统一书写 **Pikoo**，读 **pī kū / pee-koo**，名字两个音节均为平调。新连接和重连都带相同人设，设备与模拟器唤醒招呼统一提交“你好 Pikoo”，旧转写中的汉字不会改变名字。文字转写正确不能替代实际发音听感验收。

近期上下文和家庭记忆沿用[既有规则](context-memory.zh-CN.md)：不猜说话人，不把含糊的个人偏好归给某位成员，不保存凭证；纠错、删除会使旧学习失效。明确稳定事实可以主动调用记忆工具，无需先说“记住”。后台批量整理在会话关闭后运行，可能延迟或失败；本次没有承诺无限长会话中的持续提取。断线和静音期间的谈话未被听见。仍可能发生网络重连，不承诺永不掉线。

家庭唤醒录音继续仅供测试。普通合成音频只验证接口与行为，不代表儿童唤醒、AEC 或实机长期稳定性验收。

2026-10-20 验证：53 项服务器/模拟器检查、原生核心检查和 25 项工具检查通过；真实隔离网关六项行为测试通过。实机升级后保持在线倾听至唤醒后第 86 秒，记录的播放供音间隙和 I2S 错误均为 0。还需真人验证回应对象、名字发音及听感，不等于长期稳定性通过。见[实际测试记录](companion-validation.md)。

## 静默标记修复，2026-10-24

Google 原生选择性回复已开启，能够自行选择保持安静，但不是确定性的回应对象或名字
校验。Pikoo 保留这种方式和自然追问，没有增加每轮必须叫名字的限制。

Provider 曾返回 `<no speech>` 静默标记，有时带 `{pause}` 后缀。旧适配层将它当作
助手对话。新增的 `silence-output.mjs` 在展示、播放和保存助手消息之前拦截已知标记
及其开始的 PCM 音频。普通转写出现后释放正常音频；有音频但没有转写时，在回合结束
保留音频兼容路径。暂存有界，取消时丢弃，回合生命周期仍正常完成。旧助手消息中的纯
静默标记不注入 Live 重连上下文，原始记录保留；用户引用和正常英文解释不删除。

现网 Node 运行环境 43 项服务端检查通过，7 项隔离真实 Google 场景通过：前后静音、
中英文旁人交谈、中英文直接问答，以及不重复名字的英文追问。最终原生测试未生成静默
标记，标记拦截另由协议与真实 Frontend 回归验证；首次失败的后缀案例和原始结果保留。
修复已发布，原 ESP32 已自动重连，没有重新烧录。真人听感与更长家庭观察仍待验证。
